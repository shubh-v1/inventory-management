Factory Inventory Management System

An architecture overview of the demo app: a Vue 3 single-page app talks to a FastAPI service that serves in-memory data loaded from JSON files. There is no database, and no authentication beyond a mocked user.

Data flow: applying a dashboard filter

  1. User picks a filter in FilterBar: Time Period, Warehouse, Category or Order Status.
  2. Shared state updates. useFilters holds module-level refs, so every view sees the same values. getCurrentFilters() maps them to API names (location → warehouse, period → month).
  3. The view reloads data. A watcher calls api.getOrders(), api.getDashboardSummary() and the other API methods. api.js drops any filter set to "all" and builds the query string.
  4. FastAPI filters in memory. apply_filters() matches warehouse exactly and category/status case-insensitively. filter_by_month() matches YYYY-MM or expands Q1-2025…Q4-2025 to three months against order_date.
  5. The response is validated against the Pydantic response_model, or computed on the fly (dashboard summary, reports).
  6. Vue derives the display. Raw arrays live in refs. KPIs, chart series and tables are computed properties, so they recalculate automatically.

Things worth knowing

Unimplemented client calls. api.js defines /api/tasks and /api/purchase-orders methods, but main.py has no such routes, and no view currently calls them. Tasks are handled locally in App.vue through the mocked useAuth user.
Hard-coded API URL. http://localhost:8001/api is set in api.js and again in Reports.vue. There is no Vite proxy or env variable.
Partial filter coverage. Inventory has no time dimension, so the month filter doesn't apply to it. Demand, backlog, spending and reports ignore all filters. Backlog.vue exists but has no route.
Demo-grade security. CORS is open to all origins, there's no auth or rate limiting, and the repo is public.
